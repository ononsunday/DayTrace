# DayTrace 统计核心说明

DayTrace 每隔 1 或 2 秒读取一次前台应用。每个有效采样间隔只归属一个应用，多个窗口属于同一应用时合并累计。统计秒数来自单调时钟；系统日期和时间用于显示记录、拆分午夜和查询某一天。

## 轮询精度

采样只能看到检测时刻的前台应用。例如，14:00:00 检测到 VS Code，14:00:02 检测到 Chrome，这两秒按前一次采样归属 VS Code。真实切换可能发生在两次检测之间，因此切换边界有大约一个轮询间隔的误差。发生在同一轮询间隔内的短暂切换可能漏掉。1 秒采样可以缩短这个误差，也会增加检测次数。

软件不会同时给前台和后台应用累计同一段时间。无法获取进程信息时，平台层返回未知应用；没有可归属的前台应用时，核心跳过对应区间。界面显示的是数据库里已保存的记录，最多会比当前使用状态落后一个保存间隔。

## 前台模式与活跃模式

前台模式持续统计前台应用，适合阅读、视频和游戏。活跃模式还读取最后一次键盘或鼠标操作距现在的秒数，不读取输入内容。默认超过 300 秒无操作就暂停累计。

活跃模式按阈值截断区间。例如，上一采样已空闲 299 秒，两秒后空闲 301 秒，这个间隔只累计第一秒。空闲后恢复操作时，只累计最后一次输入之后可以确认的部分。同一采样间隔内先达到阈值再恢复操作，核心分别保留空闲前和恢复后的有效部分。

Windows 只提供最后一次输入时间。两次采样之间如果发生多次输入，核心无法还原所有输入时刻；在空闲恢复场景中，较早的有效活动可能少计。无法读取空闲时间、空闲计时值异常或无法解释其变化时，活跃模式舍弃该区间。

单调时钟与墙钟存在小差异时，记录边界按墙钟跨度同比换算，累计秒数仍使用单调时钟。这样短暂恢复的有效尾段不会因为两种时钟的小差异而消失。

## 无法确定归属的时间

核心会舍弃以下采样区间：

- 两次采样相隔超过 6 秒，包括系统休眠、调试暂停和较长的程序挂起。
- 墙钟倒退，或墙钟经过时间与单调时钟经过时间相差超过 0.5 秒。
- 任一端处于锁屏或不可检测状态。
- 前一次采样没有可统计的应用，或该应用已加入排除列表。

暂停、恢复和修改模式会清除上一采样基准，避免把暂停期间累计到某个应用。重复或乱序的采样不会改变基准。系统调时产生的不明区间会被舍弃；调时之后的新有效区间仍正常记录，即使它的显示时间恰好与历史记录相同。

跨午夜的记录按本地日期拆分，累计秒数按区间比例分配。手动日记保存在独立表中，填写运动、外出或阅读时间不会增加电脑使用总时长。

## 保存与失败重试

应用切换时和默认每 30 秒时，核心批量写入 SQLite。连续且没有间隙的同应用、同模式记录会合并；空闲、锁屏和重启留下的间隙会保留。后台没有每秒写入数据库。

数据库使用 WAL 和完整同步。每批统计记录及其摄取指纹在同一事务中提交。核心在成功保存后才清空待保存记录；失败时冻结原批次，避免后续追加改变它的身份。即使调用层在提交成功后报错，重试也不会增加重复时间。每个实际统计事件还有独立标识，因此调时后的新事件不会被误认为旧事件重试。

意外终止仍可能丢失尚未提交的记录，通常是最近一个保存间隔内的时间。如果磁盘写入持续失败，这个窗口可能更长。待保存记录最多保留 4096 段，达到上限后会先尝试保存，失败则向服务报告错误，不继续扩大列表。

恢复数据库前会检查版本、完整性、外键、时间段、应用信息、设置类型和日记标签。导入在一个事务中完成；验证或导入失败时，现有数据保留。高于当前支持版本的数据库在启动时会被拒绝，版本号不会被覆盖。

## CSV 与 JSON

CSV 是带 UTF-8 BOM 的统一表格，可在 Excel 中按 `record_type` 筛选：

| record_type | 内容 | 常用列 |
| --- | --- | --- |
| automatic | 自动统计的前台使用记录 | day、app_name、category、start、end、seconds、mode |
| diary | 手动生活日记 | date、completed、mood、body、tags |
| app | 应用名称、分类和排除设置 | app_key、name、category、executable、excluded、icon |
| setting | 软件设置 | setting_key、value |

计算电脑使用总时长时，只筛选 `automatic` 并合计 `seconds`。日记行的 `seconds` 留空。表中还保留数据库原始字段，未用于该类记录的列留空。`tags` 和设置的 `value` 使用 JSON 文本，便于保留列表和设置类型。

CSV 中以 `=`、`+`、`-`、`@`、制表符、回车或换行开头的文本会加一个前置单引号，防止 Excel 将内容解释为公式。开头的空格不会绕过这个处理。这个保护会改变 CSV 中相应文本的字面值。

JSON 导出保留原始内容，不添加保护单引号，包含 `sessions`、`apps`、`diaries` 和 `settings`。需要无损保留正文或自行写脚本处理时，使用 JSON。JSON 中 `diaries.tags` 和 `settings.value` 保留数据库里的 JSON 文本，需要再解码一次才能得到列表或原生设置值。完整数据库恢复使用 SQLite 备份文件，CSV 和 JSON 用于查看与分析。

## 验证范围

核心测试使用模拟应用和时间数据，验证前台归属、空闲阈值、暂停、异常间隔、调时、午夜拆分、重试、备份恢复和导出。可以在项目目录运行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_tracker.py tests\test_repository.py -q
```

这些测试没有触发真实 Windows 锁屏或休眠。真实锁屏与解锁、休眠与唤醒、全屏游戏、权限受限进程、托盘退出和长时间资源占用仍需要在 Windows 上单独验证；当前验证报告说明已经执行了哪些检查。
